操作路线：准备完整文本和输出缓存 → 按需选择【解析 JSON／按分隔符切分】→ 返回成功后读取结果。

@ 准备数据
@ 取出 JSON 字段和值
@ 按指定字符拆分文本
@ 处理失败结果

# 准备数据

不需要初始化或固定循环；每次有一条完整文本需要处理时调用。

串口分次收到的数据由外部先拼成完整文本，再传入实际字节数，长度不包含末尾的 `\0`。

# 取出 JSON 字段和值

准备字段名缓存 `keys`、字段值缓存 `values`，两者均按二维字符数组存放。

调用 `SERVER_JSON_ParseObject()` → 传入文本、实际长度、两块缓存首地址、各自每行字节数、最大字段数及 `out_pair_count` 地址。

返回 `SERVER_JSON_OK` → 按 `out_pair_count` 读取结果，同一行的 `keys` 与 `values` 一一对应。

字段值以文本形式输出；需要数值时由业务转换，字符串的外层双引号已去掉。

只用于无嵌套对象；不支持数组、嵌套对象，字符串转义不会还原。

# 按指定字符拆分文本

需要按逗号、冒号等字符拆分普通文本时 → 调用 `SERVER_JSON_SplitByDelimiter()`。

传入文本、实际长度、分隔字符 `delimiter`、输出缓存 `fields`、每行字节数、最大字段数及 `out_field_count` 地址。

返回 `SERVER_JSON_OK` → 按 `out_field_count` 顺序读取 `fields`；连续分隔符之间会保留空字段。

# 处理失败结果

输出缓存每行都要为末尾的 `\0` 留一个字节，字段数量不能超过实际分配的行数。

返回 `SERVER_JSON_OUTPUT_FULL` → 增大对应缓存的行宽或行数后重试。

其他非成功结果 → 本次结果不用于业务，先检查输入格式及参数。

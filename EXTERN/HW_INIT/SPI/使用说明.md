操作路线：固定准备 → 初始化 → 控制片选并启动传输 → 等待完成 → 释放片选。

@ 固定准备
@ 初始化
@ 启动传输
@ 等待完成

# 固定准备

在调用文件中引用 `HW_INIT/SPI/SPI_init.h`；初始化放在启动阶段执行一次，传输放在主循环按需执行。

选择接线 → 使用头文件中的 SCK／MOSI／MISO 引脚枚举 → 确认封装引脚可用，DMA1 通道 1、2 未被其他功能占用，并准备业务控制的片选 GPIO。

# 初始化

开始使用 → `HW_SPI_DMA_init()`，依次传入 `SPI_BUS1`、SCK、MOSI、MISO → 返回 `HW_SPI_STATUS_OK` 后传输。

只发送 → 将 MISO 参数设为 `MISO_NULL` → 使用发送接口；`MOSI_NULL` 为接收预留，当前没有独立接收接口。

核对从机要求 → 检查 `SPI_init.c` 的 `HW_SPI_CPOL`、`HW_SPI_CPHA`、`HW_SPI_BAUDRATE_PRESCALER` → 当前默认模式 3、128 分频，数据为 8 位、高位先行。

# 启动传输

需要发送 → 业务拉到从机要求的有效片选电平，再调用 `SPI_Transmit_DMA()`，传入发送数组和非零字节数 → 检查启动状态。

需要同时收发 → 配置实际 MOSI 和 MISO 后调用 `SPI_TransmitReceive_DMA()`，传入发送数组、接收数组和非零字节数 → 检查启动状态。

启动返回 `HW_SPI_STATUS_OK` → 保持数组有效、容量足够，发送数据不改写，接收数据不提前使用 → 等待本次传输结束。

# 等待完成

传输成功启动 → 在允许 DMA 中断运行的主循环调用 `SPI_WaitAndCheckEndOfTransfer()` → 根据最终状态处理结果，再释放片选。

启动失败 → 释放本次片选并处理返回状态 → 不按成功传输处理；返回 `BUSY` 时不要干扰已有传输的片选与缓冲区。

查看进度 → `SPI_DMA_Flag` 为 1 表示正在传输，0 不能独立证明成功 → 以等待函数返回值确认结果。

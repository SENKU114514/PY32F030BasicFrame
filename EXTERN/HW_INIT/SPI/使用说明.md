操作路线：固定准备 → 选择芯片和引脚 → 初始化 SPI → 发送或收发数据 → 确认传输结果。

@ 固定准备
@ 选择芯片和引脚
@ 初始化 SPI
@ 发送数据
@ 收发数据
@ 确认传输结果

# 固定准备

-> 在调用文件中引用 `HW_INIT/SPI/SPI_init.h`；启动阶段初始化一次；需要通信时调用传输接口。

# 选择芯片和引脚

-> PY32F002B：SCK 使用 `SCK_B0`（PB0）或 `SCK_B2`（PB2）；MOSI 使用 `MOSI_A0`（PA0）、`MOSI_A7`（PA7）或 `MOSI_B7`（PB7）；MISO 使用 `MISO_A1`（PA1）、`MISO_B6`（PB6）或 `MISO_C1`（PC1）。
-> PY32F002B 引脚复用均为 AF0，`MISO_B6` 为 AF2；PB6 会占用 SWDIO，PC1 复用 OSCIN；按实际封装确认引脚已引出。
-> PY32F030：按 `SPI_init.h` 中的 SCK、MOSI、MISO 枚举选择引脚；确认封装引脚可用，DMA1 通道 1、2 未被其他功能占用。
-> 两种芯片均由外设驱动控制 CS；使用显示屏时，D/C（RS）也由显示驱动控制。

# 初始化 SPI

-> PY32F002B 启动时调用 `HW_SPI_Polling_Init()`，依次传入 `SPI_BUS1`、SCK、MOSI、MISO；只发送时 MISO 传 `MISO_NULL`；返回 `HW_SPI_STATUS_OK` 后传输。
-> PY32F030 启动时调用 `HW_SPI_DMA_init()`，依次传入 `SPI_BUS1`、SCK、MOSI、MISO；只发送时 MISO 传 `MISO_NULL`；返回 `HW_SPI_STATUS_OK` 后传输。
-> 需要匹配从设备时，检查 `SPI_init.c` 顶部的 `HW_SPI_CPOL`、`HW_SPI_CPHA` 和 `HW_SPI_BAUDRATE_PRESCALER`；默认模式 3、128 分频、8 位、高位先行。

# 发送数据

-> PY32F002B 需要发送时，先选中外设并保持 CS 有效；调用 `HW_SPI_Transmit_Polling()` 传入数据地址和非零字节数；返回后发送已完成，可释放 CS。
-> PY32F030 需要发送时，先选中外设并保持 CS 有效；调用 `SPI_Transmit_DMA()` 传入发送缓冲区和非零字节数；启动成功后保持缓冲区有效，等待传输完成后释放 CS。

# 收发数据

-> PY32F002B 需要全双工收发时，初始化时传入实际 MOSI、MISO 引脚；调用 `HW_SPI_TransmitReceive_Polling()` 传入发送缓冲区、接收缓冲区和非零字节数；返回成功后接收数据可用。
-> PY32F030 需要全双工收发时，初始化时传入实际 MOSI、MISO 引脚；调用 `SPI_TransmitReceive_DMA()` 启动传输；保持两个缓冲区有效，等待传输完成后读取接收数据。
-> 收发期间接收缓冲区容量不得小于传输字节数；`MOSI_NULL` 当前没有独立接收接口，不用于收发流程。

# 确认传输结果

-> PY32F002B 轮询接口同步等待；返回 `HW_SPI_STATUS_OK` 表示传输完成，不需要调用 DMA 等待函数。
-> PY32F030 DMA 启动接口返回 `HW_SPI_STATUS_OK` 后，调用 `SPI_WaitAndCheckEndOfTransfer()` 获取最终结果；只有等待接口返回 `HW_SPI_STATUS_OK` 才表示完成。
-> `HW_SPI_STATUS_INVALID_ARG` 表示参数无效；`HW_SPI_STATUS_UNSUPPORTED` 表示芯片、引脚组合或操作不支持；`HW_SPI_STATUS_NOT_READY` 表示尚未初始化；GPIO、SPI 或 DMA 初始化失败时按对应状态处理；`HW_SPI_STATUS_TIMEOUT` 表示等待超时。
-> PY32F002B 不支持 DMA；DMA 初始化、传输和等待接口返回 `HW_SPI_STATUS_UNSUPPORTED`，不要用 `SPI_DMA_Flag` 判断轮询状态。
-> PY32F030 的 `SPI_DMA_Flag` 为 1 表示 DMA 正在传输；以 `SPI_WaitAndCheckEndOfTransfer()` 的返回值确认最终结果。

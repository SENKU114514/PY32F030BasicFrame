# 固定准备

在调用文件中引用 `HW_INIT/USART/USART_init.h`；初始化放在启动阶段，每个 UART 一次，收发放在主循环按需执行。

# 初始化

开始使用 → `HW_UART_init()`，依次传入 `UART1`／`UART2`、TX 引脚、RX 引脚、波特率 → 返回 `HW_UART_STATUS_OK` 后收发。

选择引脚 → 对照 `UART_TX_Pin_e`、`UART_RX_Pin_e` 的外设映射 → 确认 TX／RX 都支持所选 UART、封装引出且未被其他功能占用。

# 发送数据

需要发送 → `HW_UART_Send()`，传入 UART、数据地址和非零字节数 → 阻塞等待发送结束并检查状态；支持含 0x00 的二进制数据。

# 一次性接收

需要等待一段不定长回复 → `HW_UART_Receive_IT()`，依次传入 UART、接收数组、容量、实际长度变量地址、总超时 ms、静默超时 ms → 阻塞等待结束。

设置接收参数 → 容量和两个超时均大于 0，在主循环且全局中断开启时调用 → 首字节到达后持续静默达到指定时间，或达到总超时后返回。

接收接口返回 → 按实际长度读取本轮从数组下标 0 保存的数据 → 即使返回 `TIMEOUT`、`BUFFER_OVERFLOW` 或 `RX_ERROR`，也可能已有部分数据。

选择一次性模式 → 仅捕获本次调用建立接收窗口后到达的字节，窗口内数据不同时进入环形缓冲区 → 快速回复或连续数据宜选择持续接收，避免窗口前数据遗漏。

# 持续接收

需要持续接收 → 初始化后由中断保存数据，主循环及时调用 `HW_UART_ReceiveRingBuffer_IT()` → 每次调用前将长度变量设为接收数组容量，返回后作为实际读取长度。

检查读取结果 → `OK` 使用数据，`NO_DATA` 等待下一轮，`BUFFER_OVERFLOW` 表示曾丢数据但本次仍可能返回数据 → 根据业务处理。

同一个 UART 正在一次性接收 → 环形读取返回 `BUSY` → 等本次接收结束再切换模式。

# 处理逐字节回调

需要逐字节处理 → 在业务文件实现同名 `HW_UART_RX_IT_Callback()` → 按 UART 编号处理 `received_data`，在中断中尽快返回，不执行阻塞接收。

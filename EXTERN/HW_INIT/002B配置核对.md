# HW_INIT 的 PY32F002B 兼容配置

在原文件中通过 `#if defined(PY32F002BPRE)` 选择 002B 分支，原 F030 分支保留。工程已有的 `PY32F002Bx5` 由芯片头文件转换为 `PY32F002BPRE`，应用无需再手动定义这个内部宏。移植时仍需使用目标芯片对应的 CMSIS、LL 库、启动文件和工程芯片宏。

核对依据：本工程 `PY32F002B.pdf` 数据手册第 22 页的复用表，以及普冉 [PY32F002B 参考手册 V1.1](https://www.puyasemi.com/download_path/用户手册/MCU/PY32F002B系列参考手册_V1.1.pdf) 的 GPIO、TIM、PWR、IWDG、I2C 章节。封装是否引出对应引脚，仍须结合实际型号确认。

| 模块 | 002B 配置与处理 |
|---|---|
| GPIO / USART / I2C 引脚 | 现有 002B 映射与数据手册相符，本次未改映射 |
| TIM | 补入下表 PWM 映射；TIM14 仅向上计数；阻止 PWM 覆盖已运行的 MAG 时基，周期中断初始化也检查已配置的通道 |
| I2C 接收 | 保留最后三字节的 ACK/BTF/STOP 顺序；002B 在等待最后一个字节的 BTF 时恢复调用前中断状态，避免整个等待过程关中断 |
| IWDG | 写 PR/RLR 前等待 PVU/RVU 清零；保留原始 reload 参数语义 |
| LOWPOWER | 使用 002B 的 PWR_CR1.LPR、SRAM_RETV、HSION_CTRL、FLS_SLPTIME；避开 F030 的 PLL、VOS、DMA 配置；返回前恢复原 PWR_CR1 |
| SPI | 002B 无 DMA，现有 DMA 接口返回 `HW_SPI_STATUS_UNSUPPORTED`；F030 DMA 实现保留，未新增轮询 SPI |
| ADC | 原本为空壳，未增加功能 |

## 002B PWM 映射

| 通道 | 引脚与 AF |
|---|---|
| TIM1_CH1 | PA0 / PA5：AF2 |
| TIM1_CH2 | PA1 / PA3 / PB0：AF2 |
| TIM1_CH3 | PA4 / PB5：AF2；PB2：AF3 |
| TIM1_CH4 | PA2 / PA7：AF2；PB1：AF3 |
| TIM14_CH1 | PA4 / PA5 / PB5 / PB7：AF5 |

通过已有 `HW_TIM_PWM_init()` 使用，如 `HW_TIM_PWM_init(TIM14, PWM_TIM14_CH1_A4, 1000, 50)`。仅在返回 `HW_TIM_STATUS_OK` 时初始化成功。MAG 已使用 TIM1 时请选择空闲定时器；当前初始化接口不支持向已运行定时器追加 PWM 通道。

002B 低功耗配置位于原 `LowPower.c` 顶部：`LOWPOWER_002B_REGULATOR` 默认 `LL_PWR_LPR_MODE_LPR`，也可选 `LL_PWR_LPR_MODE_MR`。SRAM 保持由 LDO 供电；唤醒等待 MR 稳定，Flash 唤醒延时为 5 μs。F030 的 Stop1 1V2/1V0 配置不用于 002B。当前恢复流程支持框架的 HSI 4/8/24 MHz，AHB/APB/HSI 分频均为 1；其他时钟组合返回不支持。

`HW_IWDG_Init(uint8_t FeedTime)` 的 `FeedTime` 是直接写入 RLR 的值，不是精确毫秒数。LSI 标称 32768 Hz、分频 32 时，超时约为 `(FeedTime + 1) × 32 / 32768` 秒，还受 LSI 误差影响。原接口参数为 uint8_t，不能用它传入 1000 来设置 1 秒。

## 验证范围

ARMCC 分别编译 PY32F002Bx5 和 PY32F030x8 的全部 HW_INIT C 文件，均为 0 错误、0 警告。当前 Keil 源文件集合编译、链接通过；另强制链接 LOWPOWER 和 SPI 的新增条件分支接口通过。APP_INPUT 的现有未使用变量警告未处理。未执行 IAR 编译或上板验证。

本次未修改工程文件中的编译选择，也未修改 APP、SYS、MAG、SERVER、RTOS。LOWPOWER 和 SPI 在原工程中仍排除编译；低功耗的实际电流、按键唤醒、通信边界时序需要上板验证。

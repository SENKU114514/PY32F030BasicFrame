操作路线：加入工程 → 配置系统时钟 → 启动外设。

@ 加入工程
@ 配置系统时钟
@ 启动外设

# 加入工程

-> 把 EXTERN 放在工程目录中，将 EXTERN 根目录加入头文件搜索路径，将 SYS/system_init.c 加入编译。
-> 保留目标工程自己的 main.h、CMSIS 启动文件和设备 system 文件；本模块通过 main.h 中的设备头文件识别工程芯片宏，不按目录名判断芯片。
-> 工程定义 PY32F002Bx5 → 设备头文件自动定义 PY32F002BPRE → 使用新增的 002B 分支；原 F030 工程继续使用原时钟实现。
-> 当前仓库的 Keil/IAR 已将 SYS 加入编译；移入其他工程时也需加入源文件，搜索路径不会自动加入源文件。

# 配置系统时钟

-> 在调用文件包含 SYS/system_init.h，启动后、外设和 MAG 初始化前调用一次 SYS_ClockConfig，参数单位为 MHz。
-> 002B 可传 4、8、24；原 F030 分支可传 4、8、16、24、48；返回 SYS_CLOCK_OK 才继续初始化。
-> SYS_ClockConfig 收到不支持的频率 → 返回 SYS_CLOCK_UNSUPPORTED，不修改当前时钟。
-> 原 APP_SystemClockConfig(FRE) 接口继续保留；002B 下不支持的频率保持当前时钟不变，需检查结果时使用 SYS_ClockConfig。
-> 当前 main.c 在业务初始化前调用 SYS_ClockConfig 并检查返回值；其他工程接入时避免保留同名不同参数的本地函数。

# 启动外设

-> 时钟配置成功后 → 再初始化外设和 MAG → 进入主循环；时钟接口会更新 SystemCoreClock 和 LL 毫秒延时使用的 SysTick。
-> MAG 运行期间不要直接切换时钟；需要切换时，暂停业务，配置时钟后重新初始化相关外设和 MAG 时基。
-> SYS 不会自动调用业务或 MAG；上电入口仍由目标工程 main.c 管理。
